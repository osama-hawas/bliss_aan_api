## Decisions (owner, 2026-11-19)

| # | Decision | Supersedes |
|---|---|---|
| QA-D1 | The client may reject one live offer, reason optional. Offer status `rejected` (client-visible), `rejected_at`, `rejection_reason`. `POST client/offers/{id}/reject` (`OfferRejecter`). The provider stays `offer_sent`, is notified (E60 `offer_rejected`, preference `offers`) and may send a new offer. | slice-5b §5 "client declining one offer" out of scope |
| QA-D2 | A request in `offers_received` with no live offer left (withdrawn or rejected) goes back to `awaiting_offers` (history `request_awaiting_offers`, visibility all). `RequestOfferStatus`. Expiry alone does not move it yet. | D105 |
| QA-D3 | Withdrawing an offer and declining: reason required, explanation optional. A plain decline (`new`) still needs the explanation (D51). | D91 (explanation part) |
| QA-D4 | Weekly working hours restrict availability: a closed weekday is an unavailable date; a direct request or an acceptance outside her hours → `409 SLOT_UNAVAILABLE`. A provider with no hours set is not restricted. | D82 |
| QA-D5 | An address pin must be within `requests.max_distance_from_city_km` (initial 60) of its city's center (`cities.center_lat/lng`, launch cities filled by migration). Null setting or no center = no limit. Checked on inline request addresses and on saved-address creation. | — |
| QA-D6 | Signing in with a number of another account type → `403 WRONG_ACCOUNT_TYPE` with `errors.account_type` and a message naming the type. | generic `FORBIDDEN` |
| QA-D7 | Guests count and profile name keep no upper limit (owner: "leave it open"). | — |
