| # | Decision |
|---|---|
| D285 | Slice 19 scope: ledger adjustments, finance overview, provider balances, cross-provider ledger list, reconciliation. Payments / refunds / payouts screens stay S10 / S11. |
| D286 | An adjustment is a `ledger_adjustments` record; posting writes exactly one append-only `provider_ledger_entries` row (`type adjustment`, `entry_key adjustment:{id}`). Never edited or deleted; a mistake is corrected by an opposite adjustment. |
| D287 | `finance.process` requests, approves and rejects adjustments; `finance.view` reads every finance view. No new permission name; seeder unchanged. |
| D288 | Limits are settings seeded `null`: `finance.adjustment_max_amount` (null → `409 NOT_CONFIGURED`), `finance.adjustment_approval_amount` (null → every adjustment needs a second approver; set → amounts ≥ it). Snapshotted on the adjustment. |
| D289 | Four-eyes: approver ≠ requester (`409 SELF_APPROVAL`); the requester may cancel her own pending request. |
| D290 | A debit may take available below zero (as D220); the dashboard warns. |
| D291 | A posted adjustment is available immediately (no hold). |
| D292 | Reason categories: `payout_returned` (credit, a paid payout of hers, ≤ its amount, once — closes S11's "bounced transfer" note), `booking_correction` (booking of hers), `goodwill` (credit), `penalty` (debit), `other`. Free text internal. |
| D293 | Provider notified on posting only: E35 `ledger_credit_posted`, E36 `ledger_debit_posted` (amount + reference), target `earnings`. E37–E39 unused. |
| D294 | Finance periods are Riyadh calendar days, default current month; overview ≤ 366 days, daily ≤ 92 days. |
| D295 | Provider balances list only providers with a ledger entry or payout request. |
| D296 | Reconciliation = read-only checks + daily totals; no "reconciled" state, no automatic fix. |
| D297 | No exports in Slice 19 (Slice 21). |
